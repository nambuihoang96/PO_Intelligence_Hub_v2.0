# B-001.3 — One-input research import handoff

## Root causes

- The import UI required report text and structured JSON in separate inputs, so JSON-only and Markdown-with-fenced-JSON results did not follow one consistent path.
- The backend normalized Markdown and optional JSON separately and returned parser failures as partial imports. JSON-only input therefore did not reliably become structured Research Results.
- A report longer than the existing 2,000,000-character API limit received HTTP 422 with useful details in `error.details.errors`, while the frontend showed only the generic validation message.

The long Markdown + fenced JSON regression test reproduces the limit exactly: `content` is rejected as `string_too_long` with `String should have at most 2000000 characters`. This hotfix surfaces that exact field and limit in the UI; the existing API size limit is unchanged.

## Changes

- One intake field now accepts Markdown, TXT, raw structured JSON, or Markdown with a fenced JSON block. `.md`, `.txt`, and `.json` uploads use the same field and request payload.
- The backend deterministically detects those formats, validates structured data before saving, retains the submitted content verbatim, validates internal references, and keeps supplied evidence unverified. Malformed JSON returns HTTP 422 with JSON line/column details. Legacy `structured_json` requests remain supported.
- The frontend validates JSON syntax before submission, displays backend field/reason/fix details, preserves entered content after errors, and retains timeout/retry behavior.
- GEO now uses a native dropdown matching the Environment control, with common markets first and the full local country list; `Other / custom` still reveals the custom input.
- Added `run.bat` as the click-to-launch entry point. It invokes the existing local launcher, which starts/reuses the local services and opens the app URL in a browser.
- No database schema or migration changes.
