## Root causes and fixes

### Safe launcher

The previous hotfix could stop a Python process based on its process name and the response served on port 8000. That did not prove the process belonged to this workspace launcher. The launcher now records the workspace path, Python executable, PID, and process start time when it starts the backend. It only restarts an outdated backend when the listener PID and start time match that receipt and the workspace/executable paths match exactly. A legacy or otherwise unowned process is left running; the error gives the PID and a PowerShell command to stop it manually after the operator confirms it is the old PO Hub process.

### PO draft safety and concurrent mutations

Research Results now distinguishes `Unsaved changes`, `Saving`, `Saved`, and `Save failed`. Server-confirmed workspace state is tracked separately from the current draft. A response only updates state when it is the latest queued mutation; merging keeps newer local drafts intact. Failed writes reconcile membership from the server while retaining local PO text, and provide a retry action. Users can reverse a pending selection; writes remain serialized, and the final view follows the latest confirmed server membership. Dirty drafts trigger a browser refresh/close prompt and a confirmation before the Research/History links navigate away.

Inactive entity/finding PO drafts remain available after removing an item from the active Benchmark. Existing dimension-type selections and notes appear under **Legacy dimension assessments and notes**. Historical `po_notes` remain read-only and unchanged; old keys are shown as stored, editable PO workspace fields stay separate, and orphaned keys are never remapped automatically.
