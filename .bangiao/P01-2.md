# P01.2 — Benchmark 404 & Research Results readability

## Root causes

- `run-local.ps1` reused a backend after checking `/health`, the reports collection route and `structure-from-response`; it did not verify the report detail route or `PUT /benchmark-state`. Route existence was not checked against the HTTP method, so an older Hub API could pass the check and then return 404 during a Benchmark save.
- Research Results inherited a 960px content container and many small shared/report styles (8–12px metadata and controls). Overview cards had a 250px minimum, related entity attributes were printed as one long inline string, and the finding description appeared both in the detail summary and detail body. Scope values were rendered without filtering empty/null fields or translating keys.

## Changes

- The launcher now validates the OpenAPI title plus required Results API paths **and methods** before reusing an API and after starting a new API. It also rejects an existing frontend that does not serve the current report API module. Stale Hub and unrelated services receive distinct restart guidance; no process is killed automatically and SQLite data is untouched.
- Benchmark-state 404 now gives concise restart steps; endpoint/status diagnostics are collapsed. The optimistic UI keeps the local selection and PO draft visible, and server refresh after a failed request preserves local Assessment, Notes, Next Action, custom dimensions and explicit evidence links. A stale success response also cannot replace newer local drafts.
- Results typography uses a readable local scale, a wider responsive report container, scan-friendly cards with a three-line summary and “View Insight,” grouped detail sections, readable/non-empty scope values, and collapsed technical entity attributes. Entity benchmark actions have a separate responsive area and remain available without dimensions.
- No backend schema, database schema, migration, or API route was changed.
