# P01 — Research Results & Dynamic Benchmark

## Scope and root causes

P01 addresses the Results-to-Benchmark workflow only. Previously, entities, findings, and dimensions were treated uniformly as benchmark rows. That made findings look like products, and sequential selection/workspace writes could leave a partial save if the second request failed. PO workspace updates also used a route that could reject existing references after structured keys changed.

## Implementation

- Added `PUT /api/v1/reports/{report_id}/benchmark-state` to validate and persist selections and PO workspace in one database commit. Existing orphaned selections and entries may be retained, but invalid new references reject the whole update without partial writes.
- Added a typed request schema with unique selections; no database migration was needed.
- Research Results now use expandable insight cards. Selecting an insight adds it to the benchmark and exposes related entities as matrix rows; insights remain supporting/contextual entries, never product rows.
- Product comparison uses selected entities as rows and research-provided or PO-defined dimensions as columns. Missing observations show `Unknown / Not provided`; source evidence remains labeled unverified.
- Contextual insight assessments support reports without product entities. PO assessment, notes, and next actions save and reload using the same atomic endpoint.
